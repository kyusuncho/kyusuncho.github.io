# 퇴근하구 (AfterWork)

직장인이 집·회사·시간대·관심사 네 가지만 입력하면 **퇴근 동선 위에 놓인 평생학습 강좌**를 지도에 띄워 주는 추천 서비스의 PoC입니다. 기획부터 데이터 파이프라인, 검색·랭킹, LLM 큐레이션, 웹·미니앱 클라이언트, 운영까지 혼자 설계하고 구현했습니다.

## 문제

공공 강좌 카탈로그는 이미 충분합니다. 하지만 카탈로그가 답하는 질문은 *"이 구에 어떤 강좌가 있는가"* 이고, 퇴근길 직장인이 묻는 질문은 *"회사에서 이 강좌까지 가서, 수업을 듣고, 집에 돌아갈 수 있는가"* 입니다.

- **사용자는 점이 아니라 선분입니다.** 직장인의 기준점은 집과 회사 둘이라, 반경 검색은 동선 위의 먼 강좌보다 반대 방향의 가까운 강좌를 더 높게 칩니다.
- **LLM 프롬프트 하나로는 풀 수 없습니다.** 2만 7천 건 코퍼스, 3초 응답 목표, 원본 API의 1일 1,000건 한도도 문제지만, 결정적인 건 **권한**입니다. 강좌의 존재·만료·위치·일정은 사실이고, 그 사실을 생성할 수 있는 모델은 틀리게 생성할 수도 있습니다.
- **예산은 0원입니다.** 홈 서버 한 대, 무료 티어, 개발 계정 쿼터 안에서 매일 데이터를 새로 만들어야 했습니다.

검증하려는 가설은 하나였습니다. *게스트가 자기 퇴근 동선 위에 실제 강좌가 놓인 지도를 보면, 로그인할 만한 가치를 느낀다.*

## 해결

핵심 원칙은 **"결정론적 로직이 자격을 소유하고, 확률적 시스템은 그 안에서만 일한다"** 였습니다. 하위 문제마다 맞는 도구를 배정했습니다.

- **임베딩 — 의미.** 라벨 데이터 0건으로 카테고리별 서술문(프로토타입)과의 코사인 argmax로 분류하는 제로샷 분류기를 만들었습니다. 프로토타입 레지스트리는 해시와 리뷰어 승인으로 잠가 프롬프트성 산출물을 코드처럼 관리했고, 입력 해시 compare-and-set으로 stale write를 막았습니다.
- **검색 — 범위.** 모든 하드 게이트(만료·카테고리·일정·우회 예산)를 SQL `WHERE`에 두고, 코사인 유사도는 걸러진 집합 안에서만 계산합니다. 우회 거리는 집과 회사를 초점으로 하는 **타원**으로 모델링하고, 인덱스를 타는 외접원 프리필터와 정확한 조건의 2단 게이트로 구현했습니다.
- **생성 — 주관적 선호와 표현만.** LLM 큐레이션은 스냅샷으로 닫힌 도구, 스냅샷에서 유도된 ID enum, 후보별 근거 검증, 프롬프트 채널 분리의 **네 겹으로 봉쇄**했고, 그중 어느 것도 시스템 프롬프트에 기대지 않습니다. 모든 실패는 결정론적 목록으로 가는 단일 폴백으로 모입니다.
- **운영 — 매일 밤.** 홈 서버의 Airflow DAG가 수집·적재·임베딩·분류·배포를 돌리고, 태스크는 레포의 도구 이미지를 그대로 실행해 로직이 한 벌만 존재하게 했습니다. 재시도는 쿼터를 아끼는 쪽(원본 호출)과 멱등성에 기대는 쪽(임베딩)으로 비대칭 설계했습니다.
- **두 번째 클라이언트.** SSR을 금지하는 앱인토스 정책에 맞춰 Vite 미니앱을 별도 패키지로 만들고, Next 앱은 API 백엔드로 남겼습니다.

## 결과

- 전국 평생학습 강좌 **26,910건**을 매일 밤 갱신하는 파이프라인을 **호스팅 비용 0원**으로 운영했습니다. 스케줄 run은 약 6분입니다.
- 해시 펜스와 콘텐츠 주소 캐시 덕분에 야간 비용이 코퍼스 크기가 아니라 **변경량에 비례**합니다. 한 밤에 바뀐 21건은 임베딩 API 호출 1번으로 처리됐습니다.
- 소스별 급감 가드가 실제 장애(KSPO 26,347건 → 0건)를 잡아냈습니다. **DAG는 실패했지만 서비스는 어제 데이터로 정상 서빙**됐습니다.
- 오프라인·크리덴셜 프리 적대적 평가 하네스(인젝션 fixture 12개, 스냅샷 밖 ID, 근거 없는 인용, 프로바이더 실패)로 큐레이션 가드레일을 출시 전에 깨뜨려 봤습니다.
- 앱인토스 미니앱을 71.9kB(gzip)로 번들링했습니다. 콘솔 등록과 실기기 검증은 아직 남아 있고, 가설 자체도 **아직 검증 전**입니다.

## 배운 것

- **모델 선택보다 배분이 중요합니다.** 생성에게 자격을 맡긴 시스템은 더 강한 모델로도 고쳐지지 않고, 경계가 맞으면 약한 모델로도 충분히 동작합니다.
- **프로덕션에서만 존재하는 폴백은 테스트된 적 없는 폴백입니다.** 모든 외부 의존성을 오프라인 fixture 기본으로 만들자, 개발이 키 발급에 막히지 않았고 테스트가 결정론적이 됐으며 degradation 경로가 이미 구현된 상태가 됐습니다.
- **모르는 것은 0이 아니라 중립입니다.** 결측 신호를 0으로 매기면 데이터 공백이 랭킹 의견으로 바뀝니다.
- **배치 실패는 서빙이 아니라 운영자를 향해야 합니다.** 멱등성은 오케스트레이터가 아니라 태스크가 가져야 "다시 돌려"가 안전한 명령이 됩니다.
- **클라이언트를 하나 더 붙이면 구현 디테일이 아키텍처 결정이 됩니다.** 쿠키 없는 클라이언트가 생기자 "게스트를 무엇으로 구분하는가"가 처음으로 명시적인 질문이 됐습니다.
